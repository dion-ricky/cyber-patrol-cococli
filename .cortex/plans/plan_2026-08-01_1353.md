## Goal
Extract data from the Snowflake Postgres instance `cyberpatrol` (tables: `scan_requests`, `scan_results`, `urlscan_results`) and load it into native Snowflake tables in the existing `CYBERPATROL` database, on a schedule, so Cortex Analyst can query it via a semantic view.

## Design decisions
- **Target**: `CYBERPATROL.RAW` schema (new schema, keeps loaded tables separate from `PUBLIC`).
- **Screenshots**: excluded from the load (`scan_results.screenshot` BYTEA column skipped — not needed for analytics).
- **JSONB columns** (`urlscan_results.verdicts/page/lists/stats/visible/network_requests/security_details/response_headers`) → loaded as Snowflake `VARIANT`.
- **Load pattern**: incremental **upsert** using `MERGE`, watermarked on `updated_at`/`created_at`, so re-runs are idempotent and cheap after the first full load.
- **Mechanism**: a Python ETL script (using `psycopg` to read Postgres + `snowflake-connector-python` to write) staged as CSV/Parquet to an internal Snowflake stage, then `COPY INTO` a staging table, then `MERGE` into the final table. This avoids row-by-row inserts and is the standard "traditional extract/load" pattern.
- **Scheduling**: a Cortex Code cron job (`cron_create`) running the ETL script every N minutes (I'll default to 30 min, confirm with you), since the Postgres instance isn't reachable from inside a native Snowflake Task.
- **Connection reuse**: script reads Postgres creds from the existing `web_scanner/.env` `DATABASE_URL` (already used by the app) — no new secrets needed. Snowflake creds resolved via `~/.snowflake/connections.toml` (existing `HF38348` connection).

## Implementation steps

1. **Snowflake DDL** (via `sql_execute`):
   - `CREATE SCHEMA IF NOT EXISTS CYBERPATROL.RAW;`
   - `CREATE TABLE CYBERPATROL.RAW.SCAN_REQUESTS` mirroring `scan_requests` (request_id PK, status, error, created_at, updated_at).
   - `CREATE TABLE CYBERPATROL.RAW.SCAN_RESULTS` mirroring `scan_results` minus `screenshot` (id_scrap PK, request_id, crawled_time, website, task_id, classify_website, created_at).
   - `CREATE TABLE CYBERPATROL.RAW.URLSCAN_RESULTS` mirroring `urlscan_results` with JSONB columns as `VARIANT` (id, request_id, uuid, verdicts, page, lists, stats, visible, network_requests, security_details, response_headers, created_at).
   - Create an internal stage `CYBERPATROL.RAW.ETL_STAGE` for CSV/Parquet staging.

2. **ETL script** — new directory `web_scanner/etl/` (keeps it colocated with the app that owns the Postgres schema):
   - `web_scanner/etl/postgres_to_snowflake.py`: connects to both DBs, for each table:
     - queries Postgres rows with `updated_at`/`created_at` > last watermark (stored in a small Snowflake control table `CYBERPATROL.RAW.ETL_WATERMARKS`)
     - writes to a local temp Parquet file, `PUT`s it to the stage, `COPY INTO` a `_STAGING` table, then `MERGE` into the final table by primary key
     - updates the watermark
   - Reuses `config/settings.py` pattern for config (add Snowflake connection name env var).
   - Add dependencies (`snowflake-connector-python[pandas]`) to `pyproject.toml`.

3. **Cron scheduling**:
   - Use `cron_create` to run the script on a schedule (proposing every 30 minutes — will confirm/adjust).

4. **Cortex Analyst enablement**:
   - Once data is loaded, create a semantic view over `CYBERPATROL.RAW.SCAN_REQUESTS` / `SCAN_RESULTS` / `URLSCAN_RESULTS` (joined on `request_id`) so Cortex Analyst can answer questions like "how many gambling sites were scanned this week".
